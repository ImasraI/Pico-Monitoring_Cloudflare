# Pico Monitoring

Cloudflare Free deployment (no card or R2): follow [CLOUDFLARE_DEPLOYMENT.md](CLOUDFLARE_DEPLOYMENT.md). Set the Workers build command to `npm run build:cloudflare` and deployment command to `npm run deploy:cloudflare`. Production D1 bindings are in root `wrangler.json`. The public marketing site remains at `/`; the Pico Monitoring patient/doctor application remains at `/danto.html`. Private uploads share D1 storage, with a 400 MB payload cap inside the 500 MB database limit. The deployment applies pending migrations before publishing. Storage tests: `npm run test:free-storage`.

وب‌اپ پیکو مانیتورینگ (Pico Monitoring) برای پایش درمان ارتودنسی، با پنل‌های ادمین، پزشک و بیمار و وب‌سایت عمومی یکپارچه.

## وب‌سایت عمومی

صفحهٔ اصلی `/` پیش از ورود نمایش داده می‌شود. دکمهٔ ورود در سربرگ، فهرست موبایل و پابرگ به پنل فعال `/danto.html` متصل است. صفحات راهکار پایش، الاینر، براکت، PM ScanBox، پزشکان، کلینیک‌ها، بیماران، شواهد، منابع، مقالات و پرسش‌های متداول از نسخهٔ تحویلی همکار وارد شده‌اند. ناوبری، جست‌وجوی مقالات، فیلترها و فرم آماده‌سازی درخواست دمو فعال‌اند.

فرم `/contact` درخواست را فقط در همان صفحه آماده می‌کند و امکان کپی یا دریافت فایل متنی دارد؛ هنوز اطلاعات را به سرور یا تیم PM ارسال نمی‌کند. شماره‌های تماس، شماره‌های ارائه‌شده در فایل تحویلی‌اند. تصاویر محصول و پنل‌ها شماتیک و مفهومی‌اند؛ تصاویر واقعی تأییدشده باید در `components/marketing/content/assets.json` جایگزین شوند. راهنمای طراحی، منابع و فهرست تصاویر مورد نیاز در `docs/public-site/` نگهداری می‌شوند.

صفحات عمومی و مقاله‌ها محتوای اولیه و فراداده را روی سرور تولید می‌کنند. نشانی اصلی، پیش‌نمایش اشتراک‌گذاری، دادهٔ ساختاریافته، `/sitemap.xml` و `/robots.txt` به نشانی فعلی Site متصل‌اند. مسیرهای API و پنل درمان در نقشهٔ سایت عمومی نیستند. ورود و داده‌های درمانی از سامانهٔ موجود استفاده می‌کنند.

آزمون صفحه‌ها، لینک‌ها، فراداده، فایل‌ها و مسیر ورود، روی پیش‌نمایش محلی:

```sh
node tests/public-site.integration.mjs
```

## راه‌اندازی

```sh
npm ci
npm run db:generate
npm run build
npm start
```

پایگاه داده و فایل‌های خصوصی اسکن در D1 نگهداری می‌شوند. ساختار داده در `db/schema.ts` و مهاجرت‌های SQL در `drizzle/` قرار دارند. مهاجرت‌ها هنگام انتشار Site اعمال می‌شوند. برای اجرای محلی، مهاجرت تولیدشده باید پیش از شروع برنامه روی D1 محلی اعمال شود.

ورود هر سه نقش ادمین، پزشک و بیمار از فرم مشترک شماره موبایل و رمز عبور در `/danto.html` انجام می‌شود. پنل مناسب بر اساس نقش ثبت‌شده در سرور باز می‌شود. حساب ادمین تعیین‌شده توسط مالک با مهاجرت یک‌بارهٔ `0007_unified_mobile_login.sql` ایجاد می‌شود؛ کلید یا فرم راه‌اندازی وجود ندارد. حساب پزشک فقط توسط ادمین ساخته می‌شود. [راهنمای پنل ادمین](ADMIN_SETUP.md) شامل دسترسی‌ها، تعلیق حساب و بازنشانی رمز است.

پزشک در «افزودن بیمار» فقط نام کامل، شماره موبایل، کد ملی ۱۰ رقمی و تاریخ تولد را ثبت می‌کند. حساب بیمار همان لحظه فعال می‌شود؛ نام کاربری شماره موبایل و رمز اولیه کد ملی است. رمز با نمک اختصاصی و PBKDF2 ذخیره می‌شود. ارقام فارسی و عربی پذیرفته می‌شوند و صفر ابتدای کد ملی حفظ می‌شود. اطلاعات ورود در رسید ثبت بیمار نمایش داده می‌شود؛ برنامه خودش ایمیل یا پیامک ارسال نمی‌کند. داده‌ها و حساب‌های قبلی حفظ می‌شوند؛ API دعوت‌نامه‌های قدیمی برای سازگاری باقی مانده است.

بیمار در اولین ورود فرم اطلاعات تکمیلی را می‌بیند. مشخصات تکمیلی، سوابق و مدارک اولیه با توضیح در پروندهٔ پزشک ثبت می‌شوند. پزشک می‌تواند مشخصات را ویرایش کند و اطلاعات بالینی، فایل‌های طرح درمان و رویدادهای مسیر درمان را جداگانه ثبت کند؛ این موارد هنگام ایجاد حساب می‌توانند خالی بمانند. بیمار اجازهٔ تغییر مشخصات اولیه، اطلاعات بالینی یا فایل‌های طرح درمان را ندارد. یادداشت‌های خصوصی پزشک در حساب بیمار نمایش داده نمی‌شوند. بیمار فقط می‌تواند فایل‌هایی را که خودش بارگذاری کرده حذف کند.

بیمار از «حساب من» و پزشک از تنظیمات، با وارد کردن رمز فعلی و تکرار رمز جدید می‌توانند رمز خودشان را تغییر دهند. رمز جدید بیمار حداقل ۸ نویسه و رمز جدید پزشک حداقل ۱۲ نویسه است؛ فرم ورود محدودیت حداقل ۱۲ نویسه ندارد و رمز اولیهٔ کد ملی را می‌پذیرد. تغییر رمز همهٔ نشست‌های همان حساب را می‌بندد و ورود مجدد با شماره موبایل و رمز جدید لازم است. کد ملی ثبت‌شده در پرونده تغییر نمی‌کند. آزمون محلی این روند: `npm run test:password`.

ویرایش شماره موبایل توسط پزشک نام کاربری را به‌روز می‌کند؛ ویرایش کد ملی رمز فعلی را تغییر نمی‌دهد. پزشک‌های قبلی با شمارهٔ معتبر و یکتای ثبت‌شده وارد می‌شوند؛ ادمین باید شمارهٔ حساب‌هایی را که شماره ندارند یا تکراری است تکمیل کند. ورود ایمیلی حساب‌های قدیمی در API برای سازگاری حفظ شده است.

پیام‌ها و اعلان‌ها داخل وب‌اپ ثبت می‌شوند. اعلان هنگام بسته‌بودن مرورگر، ایمیل یا پیامک در این نسخه وجود ندارد. پیام فوری تنها در پنل پزشک برجسته می‌شود و جایگزین خدمات اورژانسی نیست.

ادمین با انتخاب پزشک، بیمارانش را می‌بیند و می‌تواند اطلاعات اولیه، تکمیلی و درمان را ویرایش کند. حذف حساب بیمار و پزشک قابل بازیابی است؛ حذف پزشک، بیماران ثبت‌شدهٔ او را نیز از دسترس خارج می‌کند. مدارک و سابقهٔ درمان حفظ می‌شوند و بازیابی از فیلتر حذف‌شده‌ها ممکن است. جزئیات مدیریت و آزمون‌ها در [راهنمای ادمین](ADMIN_SETUP.md) آمده است.

## امتیاز و پیشرفت درمان

پیش‌فرض: الاینر به‌موقع ۱۰، اسکن قابل استفاده و به‌موقع ۲۰، انجام دیرهنگام ۵ و سه مرحله متوالی به‌موقع ۱۰ امتیاز اضافه. هر مرحله فقط یک بار امتیاز می‌گیرد و هیچ مرحله‌ای در دو پاداش سه‌مرحله‌ای استفاده نمی‌شود. امتیازهای تاریخی حفظ می‌شوند. ارسال آزاد اسکن و مراحل دیگر مثل ویزیت امتیاز این سیستم را ندارند.

تعویض الاینر گزارش خود بیمار است و از آغاز بازه مجاز پزشک قابل ثبت است. الاینر قبلی باید انجام شده یا با تصمیم پزشک متوقف شده باشد. اسکن باید به مرحله مربوط وصل شود؛ امتیاز تا تأیید کیفیت توسط پزشک معلق می‌ماند. درخواست عکس مجدد، زمان و امتیاز ارسال اول را حفظ می‌کند. بازه و امتیاز اسکن پس از ارسال اول ثابت است. تأخیر پزشک در بررسی روی امتیاز به‌موقع بیمار اثر ندارد. توقف مرحله از ترتیب و پاداش نظم کنار گذاشته می‌شود و امتیاز قبلی را کم نمی‌کند.

پزشک از پرونده و برنامه درمان، قوانین بیمار، بازه مجاز و امتیاز ویژه هر رویداد را تنظیم می‌کند. اصلاح دستی امتیاز با دلیل و هویت پزشک در سابقه ثبت می‌شود؛ مانده نمی‌تواند منفی شود. قوانین جدید امتیاز تکمیل‌شده یا اسکن ارسال‌شده را بازنویسی نمی‌کنند.

ظاهر پیش‌فرض بر اساس تاریخ تولد است: زیر ۱۲ سال کودک، ۱۲ تا ۱۷ نوجوان، ۱۸ سال به بالا بزرگسال؛ بدون تاریخ تولد بزرگسال. بیمار می‌تواند ظاهر و هدف شخصی را عوض کند. کودک همراه و ستاره دارد؛ نوجوان نشان‌های ساده و پیشرفت؛ بزرگسال ظاهر رسمی بدون همراه، ستاره یا پوشش دارد. رنگ‌ها و پوشش‌های کودک بر پایه امتیازهای کسب‌شده باز می‌شوند، امتیاز مصرف نمی‌کنند و با اصلاح بعدی امتیاز بسته نمی‌شوند. رتبه‌بندی عمومی و جریمهٔ خودکار وجود ندارد.

آزمون یکپارچه روی پیش‌نمایش محلی پس از اعمال مهاجرت‌ها:

```sh
node tests/rewards.integration.mjs
```

این آزمون فقط روی localhost اجرا می‌شود و پزشک و بیمار آزمایشی می‌سازد؛ داده‌های موجود را حذف نمی‌کند. پس از اجرای مهاجرت‌ها، `DANTO_TEST_ADMIN_PHONE` و `DANTO_TEST_ADMIN_PASSWORD` را در محیط آزمون محلی تنظیم کنید. آزمون‌ها پزشک‌های آزمایشی را از طریق ادمین محلی می‌سازند؛ راهنمای کامل در `ADMIN_SETUP.md` است. نشانی اختیاری در `DANTO_TEST_URL` قابل تغییر است.
